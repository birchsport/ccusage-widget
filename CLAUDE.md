# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
swift build                      # debug build
swift run CCUsageWidget          # build + launch the floating panel
swift build -c release           # release build
./build-app.sh                   # assemble ad-hoc signed .app bundle
./build-app-notarized.sh         # signed + notarized .app + .dmg (gitignored; contains Team ID)
```

There is no test target and no linter configured. `swift build` is the only correctness gate.

## Architecture

This is a **SwiftPM executable target** (not an Xcode project) that is run either directly via `swift run` or wrapped into a `.app` bundle by the `build-app*.sh` scripts. `Package.swift` declares a single `.executableTarget` with `path: "CCUsageWidget"` and excludes `Info.plist` from the compiled sources.

The app is a background-only LSUIElement process. There is **no SwiftUI `WindowGroup`** — `CCUsageWidgetApp.swift` declares only `Settings { EmptyView() }` as a scene. The entire UI is manually constructed in `AppDelegate.applicationDidFinishLaunching` by creating a `DockPanel` (an `NSPanel` subclass) and setting an `NSHostingView(rootView: DockRootView(dock:))` as its `contentView`. Window behavior (level, collection behavior, alpha) lives in `AppDelegate.swift`, and geometry lives in `DockController.swift`. Neither is set with SwiftUI scene modifiers.

**Data flow:** `UsageViewModel` (an `@MainActor ObservableObject`) owns a `Timer.publish(every: 30)` Combine pipeline plus a `Task` that calls `runCommand()`. `runCommand(_:)` spawns `/usr/bin/env npx ccusage@20.0.20 <args>` via `Process()` (each fetch runs the daily report, `--json`, and all 5-hour blocks, `blocks --json`, concurrently; the blocks call is best-effort and never blanks the panel. The active block drives the NOW countdown, and the costliest finished block (`peakBlockCost`) stands in for the plan limit, which isn't visible locally. The "~N% used" figure is this block's cost against that peak, so it's only an estimate), with `/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` prepended to `PATH` so it resolves outside a shell session. Output is decoded into `UsageReport` / `DailyUsage` / `ModelBreakdown` and `BlocksReport` / `UsageBlock` (ISO 8601 dates with fractional seconds, via `UsageBlock.decoder`) from `Models.swift`. Because the app spawns a subprocess, **the bundle must not be sandboxed** — don't add App Sandbox entitlements.

**ccusage is pinned on purpose.** Its JSON shape changes between releases without notice — 20.x renamed each day's `date` key to `period`, which silently broke decoding under `@latest`. `DailyUsage` has a hand-written `init(from:)` that accepts either key. To bump the pin, run `npx ccusage@<new> --json`, diff its keys against `Models.swift`, then update `UsageViewModel.ccusage` (it's `nonisolated` because the subprocess closure reads it off the main actor).

**Context usage doesn't come from ccusage.** `SessionContextReader` (`SessionContext.swift`) reads Claude Code's own transcripts on a separate 5-second timer: `recent()` returns every session whose `projects/<project>/<session>.jsonl` changed in the last 15 minutes (up to 3, newest first, one NOW-card row each), falling back to the single newest session when none did. Only depth-2 files count; subagent transcripts live under `<session>/subagents/` and must be skipped. For each it reads just the file tail and takes the last non-sidechain `assistant` turn's `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`. Roots are the `claudeConfigDir` default (which `runCommand` also exports as `CLAUDE_CONFIG_DIR` so ccusage reads the same logs; note ccusage then reads *only* that dir), `CLAUDE_CONFIG_DIR` (only visible under `swift run`/Xcode; a Finder-launched `.app` doesn't inherit shell env), `~/.config/claude`, then `~/.claude`. The transcript format is undocumented and unpinnable, so the reader must stay fail-soft: return nil, never throw. Transcripts don't say whether a session uses the 1M window, so the denominator is `@AppStorage("contextWindow")` (200K default), auto-bumped to 1M when tokens exceed it.

**Settings persistence:** opacity is stored via `@AppStorage("panelAlpha")` in `ContentView`. On change, `ContentView` walks `NSApp.windows` to find the `NSPanel` and updates its `alphaValue` directly — there is no binding from SwiftUI to the panel. `AppDelegate` reads the same `UserDefaults` key at launch to seed the initial alpha. The chart range (7/14/30 days) is `@AppStorage("chartDays")`; the chart and the "N-DAY TOTALS" card both use `chartWindow(report:)`, which counts **calendar** days ending today and zero-fills days ccusage omits (it only emits days with usage). The 7-day mode shows per-bar labels; 14/30 switch to thin bars with an axis row and hover readout, and the card keeps a fixed height so toggling doesn't shift the layout.

**Cards:** every section goes through `card(id, title, trailing:, content:)` in `ContentView`, which draws the frame and a clickable title row that collapses the card to just that row. Collapsed ids persist in `@AppStorage("collapsedCards")` (comma-separated), so give new cards a stable `id` that doesn't depend on the displayed title (the totals card's title changes with the range; its id doesn't). Header extras passed as `trailing` hide while collapsed. The settings card is not collapsible; the gear toggles it.

**Edge dock:** the panel is pinned to a screen edge, right by default. The side is stored in the `dockSide` default (`left`/`right`) and set from the settings card. It can't be moved. `DockPanel.setFrame(_:display:)` passes every frame through `DockController.pinned`, which keeps the outer edge on the menu-bar screen's `visibleFrame` edge and the top 12pt below the menu bar. That covers live resize, the slide animation and screen changes, so nothing else needs to re-snap. Collapsed, the window is just the 64×164 tab (`DockTab`: 5h time left, estimated % of the block used, and today's cost and tokens). Clicking the tab calls `DockController.toggle()`, which animates the window frame. The window grows inward and downward, so the tab never moves. The window is only as big as what's visible, so a collapsed tab doesn't block clicks on the windows behind it. Don't switch to a full-size window with SwiftUI offsets. `DockRootView` owns the `UsageViewModel` (shared by the tab and `ContentView`), draws the single background (`EdgeDockedShape` rounds only the inner corners; macOS 13 has no `UnevenRoundedRectangle`), and lays `ContentView` out at the expanded size, clipped toward the tab. That way it slides out from behind the tab instead of being squeezed. `.resizable` is in the style mask only while expanded. Live resizes update `contentSize`, which is saved to `dockWidth`/`dockHeight` (without the tab width) when the resize ends. The expanded state persists as `dockExpanded`. `hosting.sizingOptions = []` stops `NSHostingView` from pinning the window to the SwiftUI content's ideal size. There is no window drag and no frame autosave. Defaults live in the `CCUsageWidget` domain for `swift run`/Xcode builds and `com.birch.ccusagewidget` for the `.app`.

**Naming gotcha:** `ContentView.swift` defines a private color constant named `borderColor` (not `border`) because `border` collides with SwiftUI's `View.border(_:width:)` modifier when used inside `.stroke(...)`.

## Info.plist and bundling

`CCUsageWidget/Info.plist` is **not** processed by SwiftPM — it's only read by the `build-app*.sh` scripts when assembling the `.app` bundle. `CFBundleExecutable` must be the literal string `CCUsageWidget` (not `$(EXECUTABLE_NAME)`, which is an Xcode build variable and won't be substituted when the plist is copied directly). `LSUIElement=YES` is what hides the Dock icon; without a proper bundle (e.g. when running via `swift run`) the binary still works but macOS may show a generic Dock entry.

## Distribution

`build-app-notarized.sh` is gitignored because it hardcodes the Team ID and keychain profile name. It builds a universal (arm64 + x86_64) release binary, assembles the bundle, signs with `Developer ID Application` + hardened runtime, submits to Apple's notary service via a stored `notarytool` keychain profile, staples the ticket, and produces both a `.zip` and a `.dmg`. **Prefer the DMG for sharing** — zips extracted with Archive Utility can materialize AppleDouble `._*` sidecars inside the bundle, which breaks the code signature seal ("sealed resource is missing or invalid"). DMGs preserve xattrs correctly.

**Build output path gotcha:** both `build-app*.sh` scripts get the binary location from `swift build <same args> --show-bin-path` rather than hardcoding it. Newer SwiftPM writes universal builds to `.build/out/Products/Release`, not the old `.build/apple/Products/Release`; a hardcoded path once shipped a stale months-old binary that still passed signing and notarization. To confirm a DMG has the current code, mount it and `strings` the binary for the pinned `ccusage@…` version.
